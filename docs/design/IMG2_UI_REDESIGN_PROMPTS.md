# Img2 一级页面重设计提示词包

## 目标

这份文档用于让 Img2 先产出经过确认的 UI 视觉稿，再由前端迁移现有功能。

本轮只重做右侧一级页面内容区。当前左侧菜单栏、Logo、导航顺序、收起方式、图标体系和选中状态已经通过，不允许重新设计。

视觉稿不是功能需求来源。页面现有功能必须全部保留，Img2 只负责重新组织信息层级、布局和视觉表达。

## 为什么不能一次生成全部页面

不同页面的信息密度差异很大：运行诊断是高密度工作区，资源中心是配置与状态页，概览是舒展的摘要页，卡带管理包含列表和空状态。如果分别从零生成，会再次得到多套不一致的侧栏、圆角、按钮和卡片语言。

正确顺序是：

1. 先生成“运行诊断”作为视觉母版。
2. 母版通过后，把母版作为后续每张图的第一视觉参考。
3. 当前真实页面截图作为第二参考，只用于识别功能，不允许照抄当前布局。
4. 每次只生成一个页面或一个明确状态。
5. 页面全部通过后，再开始迁移前端功能。

推荐生成顺序：运行诊断、资源中心、打包发布、卡带管理、全局概览、其他设置、资源配置弹窗、空状态与弹窗状态。

## 全局母提示词

下面整段提示词应放在每次生成请求的最前面。方括号内容按本次页面替换。

```text
你是一名资深产品设计总监，正在为 CartridgeFlow Developer Studio 重设计真实可开发的桌面端产品界面。CartridgeFlow 是面向专属服务开发者的 Flow、模型配方、工具、运行诊断和卡带交付工作台，不是营销网站，也不是面向普通消费者的内容应用。

本次输出：[页面名称与状态]。

输出一张完整、正视、无透视、无设备外框的 1600x900 桌面应用截图。不要输出设计说明、组件标注、色板、Figma 画板、浏览器外框或展示模型，只输出真实产品正在运行时的完整界面。

【不可改变的应用外壳】
1. 左侧菜单栏已经定稿，严格沿用参考图 C 的宽度、Logo、分组、菜单顺序、线性图标、底部“其他设置”和当前菜单高亮方式。
2. 不新增、删除、改名或重排左侧菜单，不把一级页面功能移进侧栏。
3. 只重设计侧栏右侧的页面内容区。
4. 页面必须保持桌面工具的工作效率，不得改成营销页、落地页或大幅插画首页。

【设计气质】
采用清透明亮、克制精密、略带温度的现代设计语言。专业但不老气，简洁但不空洞，精密但不死板。界面首先服务于开发者快速扫描、定位问题和重复操作。

基础背景使用中性白或接近白色的极浅灰，主要内容表面使用纯白。正文使用深石墨色。橙色只用于品牌、当前选择、关键入口和主操作。绿色只表示正常或完成，蓝色只表示信息或链接，红色只表示错误、危险或删除。灰色只用于边框、辅助文字和禁用状态，不得形成大面积冷灰区域。

建议颜色基线：
- 应用背景：#FAFBFC 到 #FCFDFD
- 主表面：#FFFFFF
- 主文字：#202832
- 次级文字：#66717D
- 弱化文字：#929CA6
- 浅边界：#E7EAEE
- 较强边界：#D9DEE5
- 品牌橙：#E26F35
- 橙色浅背景：#FFF4ED
- 成功绿：#278858
- 信息蓝：#3478C5
- 危险红：#CE5047

颜色可以在 10% 范围内微调，但所有页面必须使用同一套色彩关系。

【字体与图标】
1. 普通 UI 使用现代无衬线字体，中文清晰自然，标题有力但不过分巨大。
2. 等宽字体只用于 run_id、Flow ID、版本号、模型名、协议名、路径、时间、错误码和代码。
3. 页面主标题控制在 28-32px 视觉尺度，模块标题 16-20px，正文 12-14px，辅助文字不得小到难以阅读。
4. 图标统一使用简洁的 Lucide 风格线性图标，尺寸、描边粗细和对齐方式一致。
5. 禁止使用 emoji、手绘图标、3D 图标或同一页面混用多种图标风格。

【布局系统】
1. 使用稳定的 8px 间距体系，常用间距为 8、16、24、32px。
2. 页面内容区左右安全边距约 32px；标题区紧凑，不做巨型 Hero。
3. 组件圆角以 6-10px 为主，主要模块推荐 8px，按钮和输入框推荐 6-8px，弹窗不超过 10px。
4. 主要模块可以使用极轻微自然阴影，用于把纯白表面从近白背景中分离；阴影必须薄、淡、短，不得厚重漂浮。
5. 优先使用留白、字体层级、1px 边界和轻微明度差组织信息。
6. 避免框套框。一个区域只允许一个主要外层表面，内部优先使用分隔线、行、分组标题和浅背景，不要继续嵌套多层卡片。
7. 列表、表格、筛选器和操作栏应为真实可实现的布局，不使用仅供展示的装饰结构。
8. 页面可以不完全对称，但视觉重心必须稳定，重要工作区获得更大面积。

【缩放与滚动约束】
1. 视觉稿必须能迁移到 100%、110% 和 125% 浏览器缩放。
2. 一级页面本身不得产生横向或纵向滚动。
3. 长列表、日志、时间线、配置正文等内容只能在明确的内部容器中滚动。
4. 右侧操作按钮、状态标签、表格列和长 ID 在 125% 下不能越界、重叠或被截断。
5. 固定格式组件必须有稳定宽高，状态和数据变化不能造成布局跳动。

【交互表达】
1. 主操作使用实心橙色按钮；普通操作使用白底浅边界；危险操作使用克制的浅红或红色文字，不得比主操作更抢眼，除非当前任务就是确认删除。
2. 选中状态通过 1px 边界、浅橙背景、2px 内侧强调线或细微阴影表达，不使用大面积浓橙。
3. Hover、Focus、Selected、Disabled、Success、Warning、Error 必须看起来属于同一组件系统。
4. 动效只暗示快速淡入、边界变化或背景变化，不表现缩放弹跳。

【功能真实性】
1. 严格保留本次页面提示词中列出的所有模块、字段和操作。
2. 可以重新组合和排序信息，但不得删除功能或把功能藏进无法识别的装饰元素。
3. 使用真实、清晰、可读的中文和技术字段，不生成乱码、伪文字或无意义英文。
4. 数据可以使用提示词提供的示例值，但必须保持字段语义正确。
5. 不显示教学说明、设计规范文字、键盘快捷键介绍或“这是一个什么功能”的产品宣传。

【明确禁止】
禁止米黄色或羊皮纸式大面积背景；禁止大面积冷灰；禁止渐变；禁止玻璃拟态；禁止发光；禁止光斑、圆形装饰、渐变球和背景网格；禁止厚重阴影；禁止超过 12px 的普遍大圆角；禁止卡片套卡片；禁止巨型标题；禁止一排重复且同权重的大卡片；禁止传统工业后台的密集蓝灰表格；禁止营销 Hero；禁止无关插画；禁止改变侧栏。

请基于参考图提取功能，不照抄其现有内容布局。给出一套明显重新设计、可以由 React 和 CSS 精确实现的页面。
```

```text
- 使用红色只表达失败和删除，绿色只表达完成，橙色只表达选择、当前步骤和主入口。
- 不要让英文小标题、错误码或技术字段比中文任务标题更抢眼。

生成一张功能完整、信息清晰、真实可开发的 1600x900 桌面产品截图。
```

```text
- 不要沿用当前“多个同样大小卡片平均铺开”的结构。

- 页面级滚动为 0；环境长列表只在内部滚动。
```

## 页面四：卡带管理，有数据状态

```text
本次页面：卡带管理，已有多个开发卡带。

页面目标：开发者快速识别卡带、进入工作台，并完成少量管理操作。卡带本体是主入口，管理按钮是次级功能。

必须保留：
- 页面标题“卡带管理”和说明“设计、验证和打包专属服务卡带”。
- 顶部操作：导入卡带文件、刷新、新建开发卡带。
- Flow 分组，如“开发 Flow”，显示数量。
- 卡带名称、简短描述、卡带 ID、版本、协议、环境、运行类型和“开发中可修改”状态。
- 整张卡带区域可点击进入工作台，并有清晰但克制的进入暗示。
- 次级操作：编辑信息、绑定资源、打开目录、删除卡带。
- 删除是危险操作，但默认不能比“进入工作台”更抢眼。

布局目标：
- 宽屏下每行两个等宽卡带，卡带高度固定，左右卡带的操作列必须完全对齐。
- 不要把卡带做成电商商品卡或大插画卡。
- 避免把每个字段都做成彩色标签，技术元数据可以使用少量中性标签或紧凑字段行。
- 卡带主体与底部管理操作有清楚层级，整张卡片仍然是最主要的进入方式。
- 支持列表中超过 6 个卡带时在内容区内部滚动，页面级滚动为 0。
```

## 页面五：卡带管理，空状态

空状态应单独生成，不能从有数据页面随意删掉卡片得到。

```text
本次页面：卡带管理空状态，当前没有任何卡带。

保持与已确认母版完全一致的侧栏、标题、按钮、颜色、字体、边界、圆角和阴影。

必须保留：
- 页面标题、说明和顶部的导入、刷新、新建操作。
- 主文案“从第一张卡带开始”。
- 说明：把一个专属服务的流程、模型配方和交付方式整理成可运行、可迁移的卡带。
- 主操作“创建开发卡带”。
- 次操作“导入已有卡带”。
```

## 评审清单

每张 Img2 稿件必须逐项通过：

1. 左侧菜单栏是否与当前定稿版本一致。
2. 是否保留了页面提示词列出的全部功能。
3. 是否明显重做了内容布局，而不是只换颜色和圆角。
4. 是否与已通过母版使用同一字体、图标、颜色、边界、圆角、阴影和按钮体系。
5. 页面主次是否能在 5 秒内读懂。
6. 是否没有卡片套卡片和重复同权重模块。
7. 橙、绿、蓝、红是否严格按语义使用。
8. 是否没有渐变、玻璃、装饰光效、大面积米黄或冷灰。
9. 中文和技术字段是否清晰，没有乱码。
10. 是否可以在 125% 缩放下实现页面双轴滚动为 0。
11. 内部滚动区域是否清楚，不会让整个右侧页面滚动。
12. 所有按钮、状态、列表和输入控件是否看起来真实可交互。

任何一项不通过，都应继续要求 Img2 修改，不进入前端迁移。

## 前端迁移边界

视觉稿通过后，迁移时遵守：

1. 只迁移布局、视觉层级和组件表达，不重写已经工作的后端功能。
2. 先提取统一 token 和共享组件，再逐页迁移，禁止每页单独写一套颜色与圆角。
3. 保留现有 URL、API、按钮行为、弹窗行为和数据字段。
4. 每迁移一页都执行 100%、110%、125% 截图和页面级双轴零滚动检测。
5. 运行诊断、资源配置和设置中的长内容继续使用内部滚动。
6. 所有页面全部通过后，才删除当前过渡主题样式。
