# Creator Trusted Node Boundary Map

This map records the current closed boundary. Historical CF-TUNING@1.3 and
CF-FARP@1.4 remain read-only evidence. CF-TUNING@1.4 owns trusted-node input
facts, CF-FARP@1.5 retains the old confirmation handoff for compatibility, and
CF-FARP@1.6 owns the current Creator package boundary.

| Surface | Current contract |
|---|---|
| Trusted capability publication | Developer publishes one immutable preset and executable mapping snapshot; Base ships no business presets. |
| Whole-flow AI | Selects only creator-safe preset IDs and allowed relations, or returns a capability gap. |
| Overall adjustment | Re-runs the same strict composition contract and atomically replaces the current draft; old node reviews no longer apply. |
| Node AI | Can change only one selected node's declared Creator fields through preview and acceptance. |
| Creator UI | Shows discovery, dynamic recipe, node review, and package; no fixed-node palette or engineering entry exists. |
| Creator projection | Omits mappings, execution facts, engineering journey nodes, private state, and Developer controls. |
| Package boundary | Derives the candidate internally, validates every review and mapping, materializes CF-FARP@1.6, signs CF-CRE, and returns safe metadata only. |
| Runtime test | `demos/runtime-developer-toolkit` independently verifies CF-FARP@1.6 packages and never receives Creator session state. |

Remaining capability gaps are product data: a real project must receive the
needed trusted publications before AI can compose a recipe. They are not a
reason to expose Developer configuration inside Creator.
