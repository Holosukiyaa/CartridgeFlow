# 工程视图资源化任务书

状态：规划完成，尚未实施

关联任务：`ENG-021`

## 目标

将工程视图从“所有对象使用同一种节点卡片”调整为“业务节点、资源节点与 MCP 节点各自表达真实信息”。用户应能一眼区分节点类型、看到资源被实际引用的关系，并在外部 MCP 场景查看连接契约而非空白源码页。

本任务以当前 AI 日报外部采集卡带和用户提供的画布草图为验收参考；不引入截图识别或模拟资源。

## 设计原则

- 外部 MCP 不是黑盒。必须展示连接身份、连接器状态、认证引用、权限、调用契约和运行健康；密钥值、请求中的敏感字段绝不展示。
- 本地实现 MCP、外部连接器 MCP、不可审计 MCP 必须使用不同的详情模板和可用操作，不能共享“打开源码”这一入口。
- 业务节点展示输入、输出、绑定和执行语义；资源节点展示资源本身，不把资源伪装成普通业务节点。
- 工程视图中的资源节点是分析投影，不进入 Root Flow 的控制流，也不改变执行语义。
- 节点尺寸由内容和节点类别决定。最小尺寸稳定，内容不足时收缩，内容较多时扩展；自动布局必须使用实际或可预测的尺寸，避免连线和卡片重叠。
- 所有新的用户可见标题、说明、状态和表头使用中文；代码 ID、协议枚举、参数名、服务器与工具标识保持原样。

## 工作范围

### 1. 外部 MCP 连接详情

为资源目录和工程视图定义三种 MCP 呈现模式。

| 模式 | 适用条件 | 详情模板 | 可用操作 |
| --- | --- | --- | --- |
| 本地实现 | `cartridge_dlc` 且源码可静态解析 | 源码、内部操作图、源码指纹、运行轨迹 | 查看/编辑源码、编辑操作图、查看轨迹 |
| 外部连接器 | `mcp` / `remote` 且有连接器契约 | 连接详情、调用契约、输入输出、权限、超时与重试、认证引用、连通性与运行轨迹 | 查看连接详情、测试连接、查看轨迹 |
| 不可审计 | 缺少足以验证的实现或契约 | 已知契约、不可观测原因、风险状态 | 查看已知契约、查看轨迹 |

外部 MCP 节点标题区必须有“外部 MCP”标识，并直接显示 `server/tool`、连接状态和透明度。点击详情时进入新的“外部连接详情”模板，不再尝试读取 Python 源码，也不显示“打开源码”按钮。

资源目录/API 投影至少应提供以下非敏感字段：

- 连接器身份、服务端点的安全显示值或配置引用、服务器和工具标识；
- 认证引用名、是否已配置、权限范围和连接健康状态；
- 输入参数 schema、输出 schema、只读或副作用、超时、重试和幂等性；
- 最近一次连通性检查与调用的时间、结果和可恢复错误；
- 透明度、内部流程是否可读，以及不能读取时的原因。

端点、认证引用和日志字段必须经后端脱敏投影；不得把 token、密钥、Authorization、完整敏感 URL 或原始请求头发送到前端。

### 2. 工程节点类别标识

工程视图中每张业务节点卡片的标题行新增低饱和类别底色与中文类别标签。标签来自节点的实际语义，至少覆盖：开始/结束、交互、输入、AI 决策、处理、MCP 读取、MCP 执行、远程调用、传递、校验、路由、交付。

颜色仅用于快速扫描，不能是节点类别的唯一表达：必须同时有中文文字和图标。现有 `getNodePalette` 的类别色作为统一来源，禁止在各组件分散硬编码新的颜色映射。

### 3. 资源画布节点与拖拽

工程投影中的 `component_dependency`、模型依赖和工具依赖应成为专用资源节点。资源卡片按资源类别渲染：

- UI/交互资源：展示 HTML 或媒体缩略预览、资源名称、组件引用、类型与只读状态；外观参考草图中的资源预览卡。
- MCP 资源：展示本地/外部标识、服务与工具、连接状态及透明度。
- 模型资源：展示模型角色、供应方与模型标识、绑定状态。

资源节点通过虚线依赖边连接到业务节点，但不出现在 Root Flow 控制边中。资源卡可被选择、拖动、固定位置和缩放；拖动位置应仅保存为开发者本地工程视图布局元数据，不得写入业务流程拓扑或影响执行。删除资源节点、创建控制线、作为流程起点/终点均不可用。

“日报采集范围”对 `welcome.panel` 的组件依赖应投影为可拖动的 UI 资源预览卡，不再以通用的 `resource` 小卡代替预览。

### 4. 内容自适应尺寸与布局

移除工程视图统一的固定卡片高度。定义每种节点模板的最小宽高、可测量内容区和高度上限：

- 生命周期节点采用紧凑高度；
- 业务节点根据可见输入、输出、绑定、状态和错误行数增长；
- UI 资源卡按照预览比例和元数据决定尺寸；
- MCP 资源卡按照连接摘要和契约摘要决定尺寸。

在首次自动布局、窗口缩放、切换工程/结果视图、节点内容更新后，布局计算必须使用节点测量结果或同一套可预测尺寸函数。节点高度变化后，需要重新计算或增量修正相邻节点和边，禁止文字溢出、卡片覆盖、端口错位或由于 hover/状态变化导致画布跳动。

### 5. 详情面板和交互收口

工程视图右侧详情面板依据所选对象切换模板：

- 业务节点：保留概览、数据结构、绑定、执行等节点契约信息；
- UI/模型/其他资源：显示资源元数据和预览，不显示无意义的输入输出绑定表；
- 外部 MCP：显示“连接详情、调用契约、运行轨迹”；
- 本地 MCP：显示“内部流程、源码、运行轨迹”。

详情入口的文案必须与对象相符。外部 MCP 使用“查看连接详情”，本地 MCP 使用“查看源码”或“展开内部流程”。

## 实现边界

预计涉及的模块：

- `src/core/studio/resource_catalog.py`：资源目录的脱敏连接投影、MCP 呈现模式与健康摘要；
- `src/backend/main.py` 与 Lite API 白名单：资源详情/连通性检查接口及错误语义；
- `src/frontend/src/api.types.ts`、`api.ts`：资源详情类型与请求；
- `src/frontend/src/pages/flow-workbench/engineeringNode.ts`：资源节点投影、资源类别与可保存布局标识；
- `FlowGraphView.tsx`、`FlowNodeCard.tsx`、`flowNodeView.ts`、`nodeModel.ts`：节点模板、类别标识、测量尺寸与布局；
- `EngineeringInspector.tsx`、`McpTransparencyOverlay.tsx`：按对象类型拆分详情模板；
- 工程视图样式与针对 API、投影、拖拽、布局的测试。

不在本任务范围：接入某个真实第三方 MCP、保存真实凭证、把外部供应商源码复制进卡带、改变 Root Flow 执行协议、创建新的业务卡带。

## 分阶段交付

1. 先扩展资源目录契约与后端脱敏详情接口，并为三种 MCP 模式补齐单元测试。
2. 再实现资源节点模板和外部 MCP 详情模板，移除外部 MCP 的源码入口。
3. 实现类别标签、资源拖拽与本地工程视图布局持久化。
4. 实现内容自适应尺寸及布局重算，完成桌面与窄视口回归。
5. 用 AI 日报外部采集卡带和一个本地可解析 DLC MCP 卡带进行端到端验收。

## 验收标准

- 外部 MCP 点击详情后可看到连接器、服务/工具、认证引用状态、权限、参数/输出、超时、重试、透明度和运行状态；页面不出现空源码编辑器。
- 本地可解析 DLC MCP 仍可查看并编辑源码与内部操作图，现有 v0.9 源码指纹保护不回退。
- 工程视图中外部 MCP 节点标题明确标记“外部 MCP”，不同业务节点具有可读的中文类别标签和低饱和类别色。
- `welcome.panel` 等 UI 组件依赖以带预览的资源卡出现，能拖动且拖动后刷新保持位置；业务流程的控制边、验证结果和运行语义不变。
- 开始节点明显比复杂节点紧凑；复杂节点随信息增长；在 100% 与 125% 缩放及窄视口下没有重叠、裁剪、端口错位或文字溢出。
- 未配置外部连接器时显示“未绑定/不可运行”的真实状态；连通性检查失败返回稳定错误与恢复建议，不产生模拟成功结果。
- 前端生产构建、相关单元测试、Lite API 表面测试、流程预检均通过；使用 Playwright 验证拖拽持久化与三种 MCP 详情模板。
