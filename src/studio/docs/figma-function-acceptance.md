# Studio Figma 文案即规格 · 验收底稿

> 用途：实现前必读。Figma 里每一句可见文字都是功能规格，不是装饰、不是占位、不是「看起来像」。  
> 来源：画板 1–7（文件 `SKWif2lQTp6I2yPwVtVgvE`），实现代码 `Overlay.tsx` / `RuntimeDesk.tsx` / `stages.tsx` / `WorkspaceApp.tsx`，以及 2026-08-20 Playwright 实机点选 + 截图识别。  
> 验收标准：用户能否独立完成这件事、结果是不是当前这份方案、关掉再打开还在不在、错了知不知道下一步去哪。代码在、样子像、接口 200，都不算过关。

## 0. 怎么读这份文档

### 0.1 硬规则

1. **Figma 文案 = 产品合同。** 「来源列表」「关掉页面任务仍在后台运行」「需要一次成功，一次安全失败」全部是要落地的行为，不是 caption。
2. **静态 JSX 里的中文，默认都是被忽略的规格。** 从 Figma 生成/照抄进组件、却没有绑定数据、没有写回、没有改变下一屏的句子，一律记为「当作样式忽略」。
3. **画板底部 A–G 不是设计切换器。** 它是同一「运行台」组件必须具备的七个产品状态。实现时丢掉 FramePicker 控件可以，丢掉这七个状态不行。
4. **第二层「结果长什么样」决定运行台控件。** 字段名、类型、绑定源（`运行输入.date` / `结果.result_items` / `结果.source_url` / `结果.approved`）是运行时互动协议。运行台不得另起一套死字段，也不得把日报 Markdown 整段塞进「要点」。
5. **「试运行时人在 Runner 里看见的就是这里」在 Studio 里的意思：** 人看见的是 Studio 运行台的结果层，不是客户电脑上的 Go 壳。L2 结果面板 ≡ 运行台结果层。

### 0.2 本表状态词

| 状态 | 含义 |
|---|---|
| 当作样式忽略 | 文案进了 JSX/CSS，没有对应行为或数据 |
| 画了没接 | 控件能看见、能点选中态，但不读写真实对象 |
| 接了不能用 | 有绑定，用户路径走不通或结果是错对象 |
| 状态未实现 | Figma 用整屏状态表达的能力，代码里没有该状态 |
| 未出现 | Figma 有，产品界面没有 |
| 半接 | 只接了展示，没接写入/持久化/导航 |
| 过关 | 用户路径走得通，结果是当前方案，关掉再打开还在 |

当前结论（2026-08-21 Playwright `capture-runtime-result.mjs` + `capture-clearance.mjs` 点选 + `test/accept/z-*.png`）：**第 6 节闭环和第 1–3 节逐句规格均已接到行为。** 计数过滤画布、L2 内部步骤/搜索空态/保存节点/新建面板/空态预览/发布高级、运行台管家、复制指纹、缺必填失败、队列 运行中+排队中（耗时 —）均已点选过。
